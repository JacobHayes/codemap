# codemap: Engineering practices

How code is written and verified. Companion to `ARCHITECTURE.md`.

## Summary

1. **Do as much as necessary and as little as possible.** Every layer, flag, rule and check pays
   for itself or goes. codemap must not grow what it detects.
2. **One owner per fact.** Every flag, type, constant and rule is defined once and generated or
   imported everywhere else.
3. **Structure before tests.** Make a mistake unrepresentable with types first, then forbid it
   with a lint, and only then test for it.

## Simplicity

- **No layer whose job is to undo another.** If deleting A would leave B dead, they were one
  mistake.
- **A trait needs two implementations in the product.** Tests are not an implementation; seed
  data instead of mocking.
- **A crate needs a build boundary**: a slow or rarely changed dependency to isolate, or a
  measured build-time win. Never a crate for organization or pluggability.
- **No knob without a measured win.** Limits are named constants with their reason, not
  settings. A setting exists only when two real projects need different values.
- **No compatibility cruft before 1.0.** Rename and migrate every caller in the same change; no
  aliases, fallbacks or readers of old formats.
- **No self-test modes in the product.** Test code lives under `#[cfg(test)]` or in `tests/`.
- **No two implementations of one concept.** A gap in the product is fixed in the product, not
  with a script beside it.
- **Cull as you go.** Work in an area deletes what there no longer earns its place. Before
  deleting, check who calls it and why it existed.

## Scope

- **Above the fold first.** New work serves the above-the-fold list in `INTENT.md`. Moving
  something across the fold changes that document first.
- **Surface rent.** A new verb, flag, dimension, measure or detector cites a real use and comes
  with a test. When the use goes, so does the surface.
- **Dependencies are deliberate.** Each says why in one line in `Cargo.toml` or `package.json`
  and is added in its own commit. Prefer `default-features = false`.

## Code

- **Rust:** stable and pinned; default `rustfmt`; clippy pedantic with warnings as errors;
  `unsafe` forbidden; functions of at most 70 lines.
- **Errors return, invariants panic with their reason.** Anything a user or input can cause is
  a typed error. A broken invariant is a bug: `expect("why this holds")`, never a bare `unwrap`
  outside tests.
- **Deterministic by construction.** The same input gives the same index, findings and pixels.
  Hash-ordered collections (`HashMap`, `HashSet`) are denied because their iteration order is
  random per run and leaks into output order; `BTreeMap` and `BTreeSet` replace them. Where a
  hash map is measurably needed, use it with `#[expect(reason)]` and never iterate it into
  output.
- **Errors are typed.** `thiserror` enums per module; messages are rendered only at the edges
  (CLI, MCP, HTTP). Tests match variants, never message text.
- **Exceptions are local.** A lint exception is `#[expect(lint, reason = "...")]` at the site.
  No allowlist files, no ratchets.
- **Names carry units**: `handling_line_count`, `similarity_score_min`, `quiet_period_ms`.
- **Comments say why.** Docs and comments describe the current state; history lives in version
  control.
- **TypeScript:** strict, with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`;
  type-aware eslint, no `any`, functions of at most 70 lines; no raw colours outside the scale
  module.
- **Generated code** (TypeScript wire types) carries a header saying so and is regenerated by
  every check.

## Testing

- **Test behaviour through the public surface**: the query layer, the CLI, the HTTP API, the
  page.
- **Every detector has fixtures**: a small synthetic tree where it must fire and one where it
  must not, asserted on structured findings.
- **Every language has a fixture** covering its table: symbols, roles, concerns.
- **Property tests** where the bug would be geometric or incremental: treemap and heatmap layout
  (inside the parent, no overlap, area proportional to size, labels only where they fit), and
  indexing (an incremental index equals a fresh one).
- **Inference is tested through the cache.** Tests seed the cache with answers; no test calls a
  model or a network.
- **No tests that pin wording, counts of rules, or golden images.** Assert on derived values and
  structure.
- **One structural check beats a test per case.** Properties that hold everywhere (nothing
  spills out of its box, no internal id on screen, contrast, the 12px floor) run on every page
  of every browser test.
- **Browser tests wait on events, never on time.**
- **Every view state is listed** in a typed screenshot table, so a new view does not compile
  until it is pictured.
- **Slow or flaky tests are fixed or deleted**, never retried or deprioritized.
- **codemap indexes itself** in the check, as the large smoke test.

## The check

`mise run check` is the one gate, locally and in CI. Steps run in order, are silent when they
pass, print their log when they fail, and end with one overall line. Outside CI, formatters and
linters apply their fixes first. Target: under five minutes.

1. Format: `cargo fmt`, prettier.
2. Lint: clippy, cargo-machete.
3. Generate wire types; CI fails if they changed.
4. Web lint: tsc, eslint, knip.
5. Rust tests.
6. Web unit tests (layout properties, scale contrast).
7. Build the web app and the binary that embeds it.
8. Browser tests: behaviour specs and the screenshot walk without pictures, with structural
   checks and accessibility on every state.

Advisories (`cargo deny`) run in CI only. There is no fast tier; use the tools' own filters
while iterating. A step that runs no tests, or a missing tool, fails.

## Landing a change

- `mise run check` passes on the rebased result.
- The change has been used the way a person or agent would: indexed a fixture, read the output,
  opened the view.
- A visible change is shown: screenshots of every state it touches, in both themes, looked at
  critically against `DESIGN.md`, with what was off fixed.
- An output change is shown with a few lines of real output.
- One logical commit per unit of work, with its tests and document changes. A change that
  alters what a document says rewrites that line in the same commit.
